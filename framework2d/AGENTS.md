# AGENTS.md

Legacy Eclipse/ANT Android app (no Gradle). `framework2d` is a data-driven 2D game engine; the shipped game (Battle Checkers) is only a thin Activity shell plus XML map definitions.

## Layout

- `src/ru/framework2d/**` — the engine. `core` wires everything, `data` holds typed value objects, and `graphics`/`physics`/`logic`/`touches`/`sound` are the subsystems.
- `src/ru/fungames/checkers/**` — the app: `MainActivity` (map picker, LAUNCHER), `PlayGround` (builds `GameCore`, fullscreen portrait).
- `gen/` — aapt-generated `R.java` / `BuildConfig.java`, committed but **never edit**. Regenerated by aapt.
- `assets/config.xml` + `assets/xml/*.xml` — runtime data. `res/xml/` is empty; do not confuse the two.
- `bin/` — committed build artifacts (`classes.dex`, `framework2d.apk`). Stale copies live here; ignore them when reasoning about source state.

## Build / verify

There is no test suite, no lint task, and no CI. Verification = compiling and running on a device/emulator.

```powershell
ant build          # compiles src + gen only, does NOT package an APK
```

`build.xml` is an Eclipse-generated plain `javac` build (no aapt/dex tasks). Facts to know before trusting it:

- It hardcodes `../../Adk/platforms/android-16/android.jar` and `../../Eclipce` — fix the path or `sdk.dir` in `local.properties` (absent) before it works. `project.properties` sets `target=android-16`; manifest declares `minSdkVersion=8`, `targetSdkVersion=15`.
- `source`/`target` are `1.5`, which modern javac rejects. Raise them locally if you need to compile; do not commit that change without reason.
- APK packaging exists only via Eclipse ADT (`com.android.ide.eclipse.adt.ApkBuilder` in `.project`). No CLI path is configured.

## Architecture: the map XML is the program

`GameCore.createObjectsModel` -> `MapParser.parseMap` walks an `XmlPullParser` and dispatches every tag. Adding a feature usually means editing `assets/xml/*.xml`, not Java.

- `<direct>` / `<handler>` / `<sub>` / `<interaction>` -> `EnginesManager.connectEngine`, which reflects a class by name from `package` + `subpackage` (relative to the *parent engine's* package) + `engineName`. A wrong name fails silently at parse time; only logcat shows it.
- Any other tag -> `EnginesManager.createComponentInCurrentEntity`, which walks handlers until one reports `canCreateThisComponent(name)`. Name matching is against the component's class simple name or its `public final static String SHORT_CLASS_NAME` (e.g. `pict`, `d_touch`, `zoomer`, `l_respawn`, `cell_group`). Tag names are case-sensitive; only XML *attribute* lookup (`Property.isNamed`) is case-insensitive.
- `<context name= value= [transferValue=]/>` inside a handler or component aliases data fields into shared `DataContext`s. This pub/sub wiring in `EnginesManager.engineCreationIsOver` / `setContext` is the least obvious part of the codebase; contexts are merged by name across handlers, so ordering in the map file can change behavior.
- Attribute values are evaluated as arithmetic (`width/24`, `100*8/9`) by `DataImplementator`; `<replace name= value=/>` defines the substitution names, and `DisplayWidth` / `DisplayHeight` are pre-seeded from the display metrics. Prefix a value with `%s` to force a literal string.
- `<prototype>` defines a template; `HandlerRespawns.iterate` instantiates copies from `EntityStorage.createEntityByPrototype`. Only `<l_respawn>` inside a prototype registers it as a spawn source.

Runtime loop: `EnginesScheduler` ticks the engine tree; `GameSurface.onDraw` -> `OutputDraw.draw` -> `enginesScheduler.overDraw()` restarts it. `Engine.resources`, `Engine.entityStorage`, `Engine.enginesManager`, `Engine.enginesScheduler` are static singletons injected by the `EnginesManager` constructor — do not instantiate engines directly.

## Resources

- `GameResources` is the only loader. Maps come from `assets/xml/` (`AssetManager.list("xml")`, name is hardcoded) or from SD under `sPart/Maps`. Images resolve SD `sPart/Images/<name>.png` first, then fall back to `res/drawable` by identifier.
- `GameResources.getImageFromLocalRes` resolves through `R.string.my_package_name`, which must stay equal to the manifest package (`ru.fungames.checkers`). Change one and you must change the other.
- `assets/config.xml` is copied to SD on first run and then *replaces* the bundled copy for that install — edits to the asset won't take effect on a device that already has `sPart/config.xml`.
- `getSprite` caches by sprite name only, ignoring the column/row counts of later callers. Two sprites sharing a bitmap with different grid dimensions get the first definition.

## Gotchas

- **Source encoding is Windows-1251, not UTF-8.** 12 files under `src/ru/framework2d` contain non-UTF-8 bytes (Russian comments): `core/{Engine,EnginesManager,MapParser,DataCommunicationContext}.java`, `data/{Vector2,Vector3}.java`, `graphics/animation/HandlerAnimation.java`, `graphics/cameras/OutputGraphicalCamera.java`, `logic/players/HandlerPlayers.java`, `physics/collisions/{InteractionShapes,InteractionCircles}.java`, `physics/collisions/circleblock/InteractionCirclesBlocks.java`. Editing them as UTF-8 corrupts the comments — preserve cp1251. `changelog.txt` is cp1251 too.
- Logging is extremely verbose (`Log.d` per property, per component, per tick). Grep tags `"core"`, `"Parser"`, `"Physical"`, `"Logical"`, `"Output"` when debugging on-device; there is no other runtime feedback.
- `EnginesManager.PARALLEL_WORK` is a static flag read during construction, set from the map's `parallel` attribute by `MainActivity`. Changing it after `GameCore` is built has no effect.
- Typos in identifiers are load-bearing (`DEAFULT_MAP_DIRECTORY`, `spriteCollumnsNum`). Do not "fix" them without a repo-wide rename.
